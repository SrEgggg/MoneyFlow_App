# QA fixes — 27 September 2026

Implemented against [the original review](QA_REVIEW_2026-09-27.md). The original review is retained as the audit record. No personal database was opened, wiped, or reseeded during development; verification uses isolated fixtures.

## Changes

| Review area | Resolution |
|---|---|
| Duplicate accounts | Create/edit reject duplicate normalized names; SQLite triggers also guard insertion/renaming. Existing duplicates are preserved, never merged or deleted. Accounts shows a reconciliation notice and Move money displays a helpful message instead of asserting. Rename duplicates explicitly; legacy history remains on the original name. |
| Account balance safety | Accounts, goals, contributions, budgets and recurring amounts share bounded centavo validation. Transfers also validate resulting balances. A stale account rename preserves money recorded while the form was open; conflicting balance corrections are rejected. Manual balance correction requires confirmation and explains that it does not record income/expense. |
| Goal arithmetic | Contribution and withdrawal arithmetic use integer centavos, stored in the existing compatible REAL columns. Migration corrects tiny binary rounding residue and completion status without deleting contributions or inventing a completion date. Sub-cent targets are rejected by the repository. |
| Post-save failures | Transaction storage success is separate from recoverable refresh failures. A saved entry retains its ID; repeated use of the same in-flight request does not insert another entry. Analytics errors become a recoverable Home notice. Pull-to-refresh retries analytics. This is scoped request deduplication, not a claim of a persistent distributed idempotency protocol. |
| Backup validation | Format 7 requires complete tables/fields, rejects duplicate IDs, invalid numeric/date/type/settings values, duplicate account names and broken account/goal references before replacement. Photo validation remains. SQL restore is atomic and no longer uses silent replace-on-conflict. Valid legacy formats remain supported with version-aware missing-table rules. |
| Backup portability | Native save/open dialogs replace clipboard paths and automatic newest-file selection. Restore validates the selected file, previews its name/date/counts, then asks for explicit replacement confirmation. Cancellation leaves data unchanged. Controls stay disabled during an operation. Exports disclose that notes/photos/financial data are not password protected. |
| Backup consistency / audit | Export reads tables in a single SQLite snapshot. Revisions are included in format 7; older backups without revisions clear incompatible local revisions on replacement. Transaction revision and update now commit/roll back together. |
| Financial-day settings | Changing cutoff rebuilds derived analytics. Settings distinguishes cutoff-based budgets/reviews/advanced analytics from calendar-date screens. Restored monthly screens use the selected cutoff, and label cash flow/income retained accurately. |
| Notes and tags | Explicit null clears the field; omission retains it. Regression checks cover storage and backup. |
| Transfer search | Search and account-filter choices include receiving accounts as well as sending accounts. |
| Navigation | One Performance tools menu provides Journal, Monthly reviews, Streaks, Achievements and Advanced analytics. Removed duplicate tool rows from Overview and Calendar. Journal saving handles errors and repeated taps. |
| Account deletion | Linked-history checks disable deletion with an explanation. Repository protection remains authoritative and preserves history. |
| Accessibility | Account colors have 48dp touch areas, names, selected semantics and a visible check. Settings supporting text is larger and descriptions are shorter. |
| Loading / scale | Daily-cache replacement is atomic and uses a batch, and transaction history lazily builds individual rows instead of entire days. Full-history calculation still exists; device profiling is required before claiming a particular latency improvement or implementing further incremental caching. |
| Settings polish | Theme/preference and backup actions have processing guards and error feedback. Demo reset is only exposed in debug builds. |
| Privacy / clear data | Android automatic backup and transfer exclusions are explicit. About no longer promises an unconditional platform-wide “no cloud” guarantee. Clear all data explains that exported snapshots remain; it never silently deletes user-managed external files. Older internal snapshots are retained under the same disclosed policy. |
| Release signing | Removed debug-key fallback. Release builds require private upload credentials and fail clearly without them. See [release setup](../../RELEASE_SETUP.md). No keys were generated, replaced, committed, or uploaded. |

## Data compatibility

Schema 7 adds guards and corrects rounding residue; it does not rebuild or replace account/transaction tables. Account references remain compatible with the existing name-based schema. Converting every historic reference to immutable account IDs is not part of this migration because duplicate legacy names cannot be attributed safely without user input.

Unsupported legacy amounts and duplicate names are not silently coerced/merged. Resolve duplicate names in Accounts before exporting a backup intended for restore. Restore rejects unsupported data and keeps the current database intact.

## Verification

The regression suite adds 18 tests covering the review's failures, migration preservation, stale account edits, atomic revisions, invalid backups, backup cancellation/preview, restored navigation, and retained warnings after a saved transaction's balance refresh fails. The layout matrix now includes ten screens across five size/text configurations and both themes (100 combinations).

The category-edit widget test was corrected to await the actual save-completion feedback before reading the database. Previously a real SQLite query could wait behind a transaction whose continuation was paused in the test's fake-time zone. No application locking safeguards were removed.

Final verification:

- `flutter analyze`: no issues found.
- `flutter test --reporter expanded`: all 129 tests passed, including the 100 layout combinations.
- `flutter build apk --debug --no-pub`: succeeded; APK at `build/app/outputs/flutter-apk/app-debug.apk`.
- `:app:preReleaseBuild` without signing credentials: failed as intended at `verifyReleaseSigning`, with the explicit configuration message. This verifies the guard, not a signed release build.

Test logs are in `build/qa-fixes-final-tests.log`, `build/qa-fixes-analyze.log`, `build/qa-fixes-apk-final.log` and `build/qa-release-signing-guard.log`. Native file dialogs were tested through an injected fake; physical-device picker behavior remains unverified.
